# 自查清单：一轮 UI review 实际会抓到什么

按 `miuix` 技能的 `ui-review-workflow`（分类 → 取证据 → 最小修复 → 验证）跑，**至少 3 轮**。
下面这份是真实项目里逐轮抓到的全部不符合项，可以直接当 checklist 扫一遍自己的实现。

用法：先判断问题属于哪一类（结构 / 组件选择 / 间距形状 / 颜色排版 / 状态交互 / insets 自适应 / 无障碍），
再取证据（源码契约 / `Defaults` / 官方 Example / 用户指定的视觉），最后做**最小**修复。

## 结构、分组、组件选择

| # | 不符合项 | 依据 | 修法 |
|---|---|---|---|
| 1 | 空状态用了一张孤立的 `Card` | 设计语言：避免装饰性容器，优先留白 | 改成页面画布上的居中说明文字，不成组就不要卡片 |
| 2 | 候选项列表里塞"还没有可筛选的进程"这种**假选项** | 组件语义：候选项是选项，不是空状态 | 无候选时不渲染内容，空状态放到列表区 |
| 3 | 每行都重复同一句 `summary`（如"N 个进程/Hook 已生效"） | summary 该给"后果或上下文"，不是复读机 | 一行汇总 + 其余行只留标题 |
| 4 | 主题/枚举选项塞在对话框里，用户看到"入口没内容" | 见 `runtime-host-requirements.md`：缺 owner 时弹窗其实是崩了 | 先排查崩溃；能就地展示的就做成就地单选/下拉 |
| 5 | 纯文本单选项做成一堆 `RadioButtonPreference` | `preferences-and-menus.md`：设置行里的纯文本单选优先 `OverlayDropdownPreference` / `WindowDropdownPreference`（自带当前值显示） | 换下拉偏好；`RadioButtonPreference` 留给需要并列比较的少数项 |
| 6 | 手搓行结构（`Card` + `Column` + `Row` + 手写字号）承载设置型信息 | 决策顺序：公开组件 + 默认参数优先 | 用 `BasicComponent(title, summary, startAction, bottomAction)`，行内边距/字色/禁用态归组件 |
| 7 | **每条记录一张 Card** | 设计语言点名的失败做法（wrapping every row in a Card） | 流水型列表改成平坦行 + 默认 `HorizontalDivider`；真要分组就"一组一张 Card" |

## 颜色、排版

| # | 不符合项 | 依据 | 修法 |
|---|---|---|---|
| 8 | 用红色/`error` 表达"模块正常工作"的指标（如拦截计数） | `error` 是错误/危险角色；`Badge` 默认就是 error 容器 | 指标用 `primary`（强调）；只给**真正的失败状态**用 `errorContainer`/`onErrorContainer` 成对配色 |
| 9 | 破坏性动作与普通行长得一样 | 破坏性要能区分（红色是 `error` 的正当用法之一） | `BasicComponentDefaults.titleColor(color = error)`，并让文案承担"无法恢复"的语义（不靠颜色单独表达） |
| 10 | 硬编码 `fontSize = 11.sp` / 手写 `fontWeight` | 有语义 textStyle 就不要硬编码字号字重 | 用 `MiuixTheme.textStyles.footnote2` 等；等宽字体只在"原文日志/代码"这种确有必要处保留，并写注释说明 |
| 11 | 给导航项加红色角标表示"累计数量" | 计数不是告警；`BadgeDefaults` 是 error 容器 | 要么去掉角标、把计数放进页面；要么让角标只表示"需要关注的新事件" |

## 状态、自适应、无障碍

| # | 不符合项 | 依据 | 修法 |
|---|---|---|---|
| 12 | 关掉某个开关后，对应筛选项必然为空却没有任何解释 | 状态要显式建模，不能靠一个布尔推导 | 空状态按条件给原因（"『记录放行事件』已关闭，所以这里没有数据"） |
| 13 | 宽窗口（平板/折叠屏）下卡片横跨整屏 | 自适应矩阵：宽窗口要重新约束 | 正文 `fillMaxHeight().widthIn(max = 600.dp)` + 顶部居中，窄屏零影响 |
| 14 | 只用图标表达状态（直观/原文、开关状态） | 不得只靠图标或颜色传达状态 | 图标 `contentDescription` 描述**动作**，同时用文字写明当前状态；颜色做冗余编码而不是唯一编码 |
| 15 | 未使用的 import / 残留旧文件 | 代码契约 | 清掉；重构后 `git status` 与源码清单各过一遍 |

## 不做什么（同样重要）

- **不加**没有产品需要的 showcase 效果（诊断面板、FPS 监视、blur 试验台）；
- **不引入**额外效果库来"顺便"做玻璃——需要就先读 `glass.md` 分档；
- **不动**状态所有者、导航结构、insets 归属（铁律 7）；
- **不发明** token 或组件（没有 `success`/`warning` 就换语义组合）。

## 每轮结束要能回答

1. 这一轮改了哪些文件、每个文件一句话职责；
2. 每处改动指回哪条证据（源码契约 / `Defaults` / Example / 用户指定的视觉）；
3. 验证到第几档（编译 / lint / 产物 / 渲染 / 设备），缺哪档；
4. 剩下哪些"明知有取舍但保留"的点，以及理由。
